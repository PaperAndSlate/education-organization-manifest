# EOM 1.0 Governance and Change Control

The steward maintains the specification and reference implementation without owning independent publishers' facts. Editorial changes may be approved by maintainers. New fields, modules, profiles, semantic meaning, version policy, signatures, media/link registrations, or breaking APIs require an RFC with use cases, alternatives, compatibility, migration, security, privacy, internationalization, accessibility, provenance, and tests. Architecture changes require an ADR.

Compatible additions should preserve unknown open vocabulary values and optional fields. Breaking changes require a major version and immutable historical artifacts. Rejected and withdrawn proposals remain available for historical context. Security emergencies may receive narrow patches followed by review. Maintainer succession, conflict disclosure, and review evidence are part of release governance.
