Integrate

Keep the boundaries visible

EOM is a public interoperability layer. Your SIS, LMS, CMS, calendar, menu service, website, or district system can produce or consume EOM without making that product part of the protocol.

Controlled mappings

Source Use Boundary
Schema.org JSON-LD Organization, course, event, job, news projections EOM remains richer; arbitrary extensions are omitted.
CEDS / Ed-Fi Public organization, campus, course, program projections No person-level, enrollment, grade, attendance, or HR copying.
OneRoster / CASE Public course, offering, session, standards references Users, results, answer keys, and private assessment data stay out.
QTI / LTI / Common Cartridge Public package and service metadata No secrets, private keys, launch data, secure items, or package fetching.
iCalendar / feeds Public events and news items No attendee contacts, private organizers, executable enclosures, or active markup.

See the mapping guide and versioned mapping registry. All bundled mappings are preview-only and explicitly make no external certification claim.

Hosting modes

  • Direct: school origin serves the static resource.
  • Reverse proxy: school origin controls the public URL while a vendor operates infrastructure.
  • Static generator: approved source files build in CI.
  • Delegated: a separate district/vendor origin is linked by an explicit root scope.

A future website product may add branding, composition, workflows, and search, but public institutional facts should remain traceable to reviewed EOM source data.

Mapping tests are paper&slate tests, not external standards certification.
