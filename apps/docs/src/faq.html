    FAQ and troubleshooting

    Answers for first-time implementers

    These answers describe the current EOM 1.0 working draft and may change through the documented RFC process.

    Is EOM a student information system?

    No. It is a public institutional discovery and description format. Student records, grades, individual attendance, disability or medical records, discipline, private schedules, credentials, and internal endpoints are outside the protocol.

    Does a valid document mean the school facts are true?

    No. Schema validation proves shape. Provenance, authority, review, effective dates, freshness, and optional signatures provide separate evidence, and none alone proves factual truth.

    Why is my linked resource rejected?

    Check HTTPS, the final URL after redirects, declared media type, size and timeout limits, resource identity, scope, expiry, and any explicit cross-origin delegation. A vendor host is not automatically the school’s authority.

    Why did a private field get quarantined?

    The official adapters use public-field allowlists. Remove the prohibited field from the source export and restart the review. Do not rename a student or credential field to bypass the check.

    Can I publish YAML?

    YAML is authoring convenience only. Generate deterministic canonical JSON and serve the JSON resource at the proposed well-known path. Sign canonical JSON bytes, never YAML.

    What does “conformance” mean?

    It means a named implementation passed a named EOM profile and test suite. It does not mean accreditation, legal compliance, school endorsement, data quality, external standards certification, or IANA registration.

    Fast diagnostic loop

    1. Run pnpm eom check or paste the document into the local playground.
    2. Fix the first structural finding, then rerun semantic and privacy checks.
    3. Use pnpm eom explain <finding-code> for remediation guidance.
    4. Inspect delegation and signature dimensions independently.
    5. Compare two builds byte-for-byte before release.

    If a behavior is missing from the versioned specification, open an RFC rather than relying on an undocumented extension. See governance and reference.

    Troubleshooting output should never include private input values.
