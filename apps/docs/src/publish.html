    Publish

    A five-minute publisher path

    Start with a small organization profile and add modules when their public owner is ready. Do not publish private operational data just because a source system contains it.

    Before authoring: EOM is for public institutional information. Never include student records, grades, individual attendance, IEP/504/SEN/medical/safeguarding or discipline records, private schedules, private transportation assignments, secrets, credentials, or internal-only endpoints.

    1. Create an authoring project

    pnpm install --frozen-lockfile
pnpm eom check examples/ecme-high/source/eom.config.yaml --json
pnpm eom build examples/ecme-high/source/eom.config.yaml

    The repository’s YAML authoring model is a source format, not a wire format. The generator normalizes ordering, resolves approved local references, validates resources, and writes canonical UTF-8 JSON.

    2. Publish the root

    Serve the generated root at:

    https://school.example/.well-known/educational-organization-manifest

    Use application/json, HTTPS, GET and HEAD, bounded responses, and cache headers that match your revision process. The root should identify the publisher, organization scope, capabilities, resources, protocol version, and schema.

    3. Add optional modules

    School-owned

    Organization, campuses, contacts, departments, courses, programs, events, policies, admissions, sports, clubs, jobs, news, and public statistics.

    Delegated

    Meals, transportation, or vendor services may live on another origin only with an explicit root delegation covering origin, path, resource type or ID, subject, validity, and revocation.

    Reviewed

    Use provenance and owner review for imported or generated values. Candidates never publish directly, and conflicts are preserved for a decision.

    4. Review before release

    1. Run schema validation and semantic linting.
    2. Review privacy findings and external links.
    3. Check freshness, language tags, effective periods, and delegated scopes.
    4. Build twice and compare output bytes.
    5. Optionally sign canonical JSON with the detached signature profile.

    See the repository quickstart, authoring guide, and reference pages.
