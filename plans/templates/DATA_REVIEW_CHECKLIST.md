# EOM Data Review Checklist

## Source and authority

- [ ] Every changed fact has evidence.
- [ ] Source publisher and authority class are recorded.
- [ ] Source edition/effective date is known or flagged.
- [ ] Rights/reuse status is reviewed.
- [ ] Conflicts are visible.
- [ ] Organization-origin and external claims are not silently merged.

## Identity

- [ ] Stable IDs did not change due only to rename or path movement.
- [ ] Official identifiers use namespaced schemes.
- [ ] Entity matches use more than name similarity.
- [ ] Parent/campus/department relationships are correct.

## Courses and programs

- [ ] Course definitions are separate from offerings/sections.
- [ ] Codes and effective catalog periods are correct.
- [ ] Prerequisite logic preserves AND/OR meaning.
- [ ] Credits/levels use the correct jurisdiction system.
- [ ] Standards/qualification mappings are evidenced.
- [ ] Planned offerings are not presented as guaranteed.

## People and privacy

- [ ] No student-level information.
- [ ] Named staff fields are deliberately public.
- [ ] Role contacts are used where possible.
- [ ] Personal fields have review/freshness metadata.
- [ ] Transport/facility/statistics data received required review.
- [ ] No secrets, internal URLs, or hidden metadata.

## Language and accessibility

- [ ] Default and supported languages are declared.
- [ ] Language tags are valid.
- [ ] Translations are reviewed and sourced.
- [ ] Media includes accessible descriptions/transcripts where applicable.

## Publication

- [ ] Schemas pass.
- [ ] Semantic lint passes or exceptions approved.
- [ ] References resolve.
- [ ] Provenance coverage meets profile.
- [ ] Generated output is deterministic.
- [ ] CODEOWNERS approvals complete.
- [ ] Expiry/freshness is appropriate.
- [ ] Correction route is current.
- [ ] Publication and rollback are approved.
