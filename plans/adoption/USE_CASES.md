# Use Cases

## School website

Render organization, department, course, program, event, service, and policy pages from reviewed EOM data.

## Course catalog

Generate:

- searchable web catalog;
- department views;
- program pathways;
- printable/PDF catalog;
- Schema.org Course/CourseInstance markup;
- API and CSV projections.

## District directory

A district publishes a root manifest representing multiple schools or each school publishes its own manifest and links the district relationship. Consumers discover schools, campuses, calendars, and shared services.

## Vendor module

A meal, transport, athletics, calendar, job, or CMS vendor hosts a module. The school root grants a constrained delegation.

## Public search/index

A foundation or government service discovers manifests, stores observations, resolves identities, and exposes a convenience API while retaining the origin claim and provenance.

## AI assistant

An AI agent discovers approved structured public information, answers questions with source/effective dates, and avoids treating scraped snippets as authoritative. EOM does not authorize access to private systems.

## Accessibility and translation

Tools transform structured public fields into accessible navigation, plain-language views, translations, speech interfaces, and alternate formats. Translations retain language provenance and review status.

## Research and public data

Researchers use public aggregate information with explicit periods, methods, licenses, and suppression. EOM does not make private records public.

## School selection and course discovery

Families may search public course/program information, facilities, services, admissions links, and transport zones. Applications must explain data freshness and should not rank schools using opaque or inappropriate measures.

## Internal publishing workflow

Departments own source modules, central administrators approve release, and a deterministic build generates public resources.

## Migration and website redesign

A school moves CMS/vendors without losing the canonical public data model. The new site consumes the same EOM source or publication.

## Framework adapters

A Next.js, WordPress, Drupal, static-site, SIS, or custom platform exposes the well-known route and module resources using an adapter.

## Emergency correction

A school removes an accidentally published personal field, updates provenance, republishes, invalidates caches where possible, and alerts downstream indexes through correction workflows.
