# Licensing and Intellectual Property Plan

## Recommended licenses

### Software, schemas, generated types, tests

Apache License 2.0.

Reason:

- permissive reuse;
- explicit patent grant;
- suitable for vendor and open-source implementation;
- familiar SPDX identifier.

### Specification and documentation

Creative Commons Attribution 4.0 International.

### Example data and public vocabulary data

CC0 1.0 Universal where paper&slate has the right to dedicate it.

## Repository layout

- top-level `LICENSE` explaining multi-license structure;
- `LICENSES/Apache-2.0.txt`;
- `LICENSES/CC-BY-4.0.txt`;
- `LICENSES/CC0-1.0.txt`;
- SPDX headers or `.license` files;
- REUSE compliance.

## Schemas

Treat JSON Schemas as Apache-2.0 code. Consider dual permission/CC0 only after legal review; avoid ambiguous licensing.

## External vocabularies

Do not copy external code lists without checking:

- copyright;
- database rights;
- attribution;
- redistribution;
- modification;
- version terms.

Prefer references and mappings when redistribution is uncertain.

## Example source material

Ecme High is original fictional data. Do not adapt a real school's catalog text.

## Contributions

Use DCO or approved CLA policy. Contributor represents they have rights to submit.

## Trademarks

Names such as OneRoster, QTI, CASE, LTI, Common Cartridge, and other standards may be trademarks. Use them descriptively and follow owners' policies. Do not claim certification.

## Conformance mark

A paper&slate EOM mark, if created, is governed separately from the open specification license.

## Foundation name

Protocol implementation rights cannot depend on permission to use paper&slate branding. Third parties may say “implements EOM” under the conformance/trademark policy.
