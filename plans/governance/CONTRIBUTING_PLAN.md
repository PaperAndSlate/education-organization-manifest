# Contributing Plan

## Contributor paths

- report a bug;
- improve documentation;
- add fixture;
- propose vocabulary term;
- propose mapping;
- implement adapter;
- propose RFC;
- review internationalization/privacy/accessibility;
- pilot publisher/consumer.

## Contribution requirements

- issue/RFC link for semantic changes;
- tests;
- docs;
- changelog/changeset;
- license sign-off;
- no real private school data;
- no generated-file manual edits;
- no unrelated formatting churn.

## Commit/PR guidance

PR template asks:

- what changed;
- why;
- protocol impact;
- compatibility;
- tests;
- privacy/security;
- internationalization;
- generated output;
- RFC/ADR;
- screenshots for UI;
- checklist.

## Contributor agreement

Prefer Developer Certificate of Origin sign-off unless legal counsel selects a CLA. Avoid unnecessary contributor friction while preserving licensing clarity.

## Code of conduct

Use a recognized code of conduct with enforcement contacts and process.

## School practitioners

Provide non-code issue templates:

- field/module request;
- confusing terminology;
- publication workflow problem;
- privacy concern;
- international profile request;
- example correction.

## Review expectations

- respectful, specific;
- distinguish normative from preference;
- do not demand implementations tied to one vendor;
- explain compatibility;
- accept that schemas need restraint.

## AI-assisted contributions

Allowed when:

- contributor remains responsible;
- sources/licensing reviewed;
- tests pass;
- no private data;
- no fabricated standards claims;
- disclose material generated content when repository policy requires.

## Documentation style

- plain language first;
- precise normative section;
- examples;
- international terms;
- no unexplained acronym;
- note optional versus required.
