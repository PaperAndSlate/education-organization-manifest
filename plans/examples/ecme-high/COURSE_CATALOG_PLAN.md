## Required edge cases

Codex should make the completed catalog deliberately cover:

- a course with a simple prerequisite;
- a course with `allOf` prerequisite logic;
- a course with alternative prerequisites (`oneOf`);
- a course with a corequisite;
- a course requiring instructor/department permission;
- a repeatable performance course;
- a material fee;
- a course fee with waiver information;
- required public safety/equipment notes;
- multiple delivery modes;
- multiple languages;
- one retired course and replacement relationship;
- one planned course with no offering;
- one course offered in both semesters;
- one offering at multiple campuses if a second synthetic campus fixture is added;
- one concrete section with a fictional public instructor;
- one course mapped to a synthetic program and external standards reference;
- one approximate mapping that is explicitly not marked equivalent;
- one historical catalog version;
- one cross-listed display relationship without identity collapse;
- one intentionally invalid prerequisite cycle fixture.

- localized title and description;
- provider school and FCS department;
- grades 11–12 through a jurisdiction profile;

- prerequisite `CUL-101` with a minimum local result represented through a grading-scheme reference;

- culinary lab facility;
- material fee and waiver contact;
- outcomes and topics;
- synthetic local standards/competency references;
- related Culinary and Hospitality Pathway;
- course catalog effective period;
- source/provenance;
- separate 2027–2028 offering;
- optional section record with fictional teacher, room, and schedule only if deliberately public.

## Catalog versions

Create at least:

- `2027-2028` active catalog;
- one small `2026-2027` historical snapshot;
- one proposed `2028-2029` candidate kept out of public release output.

Stable course identity should survive catalog versions. Versioned descriptions/effective periods should not generate a new ID unless the educational entity itself changes.
